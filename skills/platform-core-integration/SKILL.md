> Program `platform_core` · IDL **0.1.0** · Anchor 1.2.1 · **devnet** `AJnPSYsn7J2muHfKztRtpZz5kBP94dWkNZLr9aMhu18G` (deploy slot 509128032)

## 0. Mental model

platform-core is a **leaf program**: it never CPIs into your program and you never CPI into it. You **pass its accounts into your instruction** and verify them yourself.

EVM comparison: instead of `core.hasRole(MODERATOR, msg.sender)` across contracts, the caller attaches the `RoleMember` account as a "certificate", and your program checks that the certificate is genuine (owner + seeds).

| Account | Seeds (program = platform-core) | Size | Who uses it |
|---|---|---|---|
| `PlatformConfig` | `[b"config"]` | 97 | fee snapshot (`boost_fee_bps`, `ad_fee_bps`) · `treasury_bump` |
| `Treasury` | `[b"treasury"]` | 42 | receives platform fees (SOL directly, tokens through its ATAs) |
| `RoleMember` | `[b"role", &[role as u8], member]` | 115 | "does this wallet hold role X?" = the account exists |
| `GameEntry` | `[b"game", game_program]` | 220 | is the game registered and `Active`? · `owner` · `game_authority` |
| `AllowedMint` | `[b"boost_mint", mint]` | 147 | may this token be used for boosts / token prizes? |
| `DefaultAd` | `[b"default_ad", width u16 LE, height u16 LE]` | 651 | fallback ad for a W×H slot |

Devnet addresses: `PlatformConfig` = `Be8StYkiu7eBMb6m3TvG7QzMZpFL69bcn1kGmZwSmrJ7` · `Treasury` = `CBcvwWyNbXKpk5GK6VczDBqaZrP1qsvBzetv7Ms5A6pz` (fees today: boost 100 bps, ad 100 bps).

Enums (Borsh = variant index; the order never changes):
`Role` = `Admin 0 · GameRegistrar 1 · Moderator 2 · FeeManager 3 · AllowlistManager 4` · `GameStatus` = `Active 0 · Suspended 1` · `FeeKind` = `Boost 0 · Ad 1`.

## 1. Setup and the three rules

```rust
// Copy idls/platform_core.json from this repo into an `idls/` folder of your workspace.
// declare_program! looks for idls/<name>.json in the nearest ancestor directory of your crate.
declare_program!(platform_core);
use platform_core::accounts::{AllowedMint, GameEntry, PlatformConfig, RoleMember, Treasury};
use platform_core::types::{GameStatus, Role};
```

- Account types generated by `declare_program!` implement `Owner` = platform-core's ID, so `Account<'info, GameEntry>` checks owner + discriminator for you.
- ⚠️ Generated types do **not** implement `PartialEq`. Write `matches!(x, GameStatus::Active)`, not `x == GameStatus::Active`.
- ⚠️ Anchor 1.2.1 hides your **own** program's `crate::cpi` behind the `cpi` feature. CPI into **other** programs through `declare_program!` works normally.

**The three rules — do not skip any:**
1. Use **`Account<'info, T>`** for every platform-core account whose data you read (owner + discriminator check). Exceptions: accounts you only send lamports to (Treasury §2.6, game owner §2.3).
2. Add **`seeds = [...]` + `seeds::program = platform_core::ID`**. Rule 1 proves it is *a* `GameEntry`; this proves it is the `GameEntry` *of this game*.
3. Check **`Active` and the allowlist only when something starts** (open, create, first bid). **Never** when paying out (claim, refund, settle, cancel). Otherwise suspending a game or removing a mint locks players' funds.

## 2. Snippets

### 2.1 The game is registered and Active (open a pool, init ad config, first bid, create a room)

```rust
#[account(
    seeds = [b"game", game_program.key().as_ref()],
    bump = game_entry.bump,
    seeds::program = platform_core::ID,
    constraint = matches!(game_entry.status, GameStatus::Active) @ MyError::GameNotActive,
)]
pub game_entry: Account<'info, GameEntry>,
```

For pay-out paths that still need `GameEntry` (e.g. to read `owner`), use the same snippet **without the `constraint`**.

### 2.2 The caller really is that game (PDA signer)

```rust
// The game program signs its CPI with seeds [b"game_authority", &[bump]] — the seed is fixed hub-wide.
#[account(address = game_entry.game_authority @ MyError::NotGameAuthority)]
pub game_authority: Signer<'info>,
```

platform-core computes and stores `game_authority` at registration, so you never call `find_program_address` for it.

### 2.3 The game owner (signing, or receiving revenue)

```rust
// When the owner must sign (e.g. configuring the game's ads or lobby):
#[account(address = game_entry.owner @ MyError::NotGameOwner)]
pub game_owner: Signer<'info>,

// When the owner only receives funds (e.g. ad settle):
/// CHECK: pinned by `address` — UncheckedAccount so settle never gets stuck
#[account(mut, address = game_entry.owner @ MyError::NotGameOwner)]
pub game_owner: UncheckedAccount<'info>,
```

- Use `UncheckedAccount` + `address` to **receive** funds, not `SystemAccount`. If `owner` were ever set to a non-system account, `SystemAccount` would make every settle fail and leave rent stuck. `address` still pins the destination, and the runtime allows crediting lamports to an account owned by another program (test `settle_pays_a_program_owned_owner_k4`).
- Owners should still be normal system-owned wallets.
- Read `owner` **at pay-out time**: if ownership is transferred, revenue goes to the new owner.
- Remaining risk: if an Admin sets `owner` to a reserved or demoted program key, `mut` is not allowed and settle still fails. Only an Admin misconfiguration can cause this.

### 2.4 A role (example: ad-pool's moderator Worker)

```rust
#[account(
    seeds = [b"role", &[Role::Moderator as u8], moderator.key().as_ref()],
    bump = moderator_role.bump,
    seeds::program = platform_core::ID,
)]
pub moderator_role: Account<'info, RoleMember>,
pub moderator: Signer<'info>,
```

- Role and member are in the seeds, so "the account exists" = "the wallet holds the role". No field checks needed.
- Check the **exact** role. `Admin` is **not** implicitly every other role in consumers.
- Revoking a role closes the account, so the next transaction fails to deserialize it (fails closed).

### 2.5 Fee snapshot (rewards-pool `open_pool*` · ad-pool first bid of a slot)

```rust
#[account(seeds = [b"config"], bump = config.bump, seeds::program = platform_core::ID)]
pub config: Account<'info, PlatformConfig>,
// ...
pool.fee_bps = ctx.accounts.config.boost_fee_bps;     // boosts
auction.fee_bps = ctx.accounts.config.ad_fee_bps;     // ads
```

Store the value in your own account. Later fee changes then never affect a pool or auction that is already open.

### 2.6 Sending fees into the Treasury

```rust
#[account(seeds = [b"config"], bump = config.bump, seeds::program = platform_core::ID)]
pub config: Account<'info, PlatformConfig>,                // for `treasury_bump`
/// CHECK: verified by seeds + seeds::program
#[account(mut, seeds = [b"treasury"], bump = config.treasury_bump, seeds::program = platform_core::ID)]
pub treasury: UncheckedAccount<'info>,
```

`Account<'info, Treasury>` (mut) also works: Anchor 1.2.1 writes data back only for accounts your program owns. You can drop `config` by hard-coding the Treasury address and bump; the seed `[b"treasury"]` never changes.

| Where the fee is before the transfer | How to move SOL into the Treasury |
|---|---|
| A user's wallet | `system_program::transfer` (CPI) |
| An escrow PDA **owned by your program** | `escrow.sub_lamports(fee)?; treasury.add_lamports(fee)?;` — a program can debit only accounts it owns, but can credit any account |

**SPL tokens — two separate moments; never combine them:**

At **boost / deposit time** (something new starts → check the allowlist; no Treasury needed):
```rust
#[account(seeds = [b"boost_mint", mint.key().as_ref()], bump = allowed_mint.bump, seeds::program = platform_core::ID)]
pub allowed_mint: Account<'info, AllowedMint>,
```

At **fee-collection time** — every line is required, and **do not add `allowed_mint`** (a mint removed from the allowlist after a boost must still be collectable, or its fee stays locked forever):
```rust
#[account(mint::token_program = token_program)]
pub mint: InterfaceAccount<'info, Mint>,
pub token_program: Interface<'info, TokenInterface>,
#[account(seeds = [b"config"], bump = config.bump, seeds::program = platform_core::ID)]
pub config: Account<'info, PlatformConfig>,
/// CHECK: ⚠️ REQUIRED pin. A bare UncheckedAccount lets a caller pass their own wallet + ATA
/// and redirect the fee to themselves.
#[account(seeds = [b"treasury"], bump = config.treasury_bump, seeds::program = platform_core::ID)]
pub treasury: UncheckedAccount<'info>,                     // read-only: authority of the ATA
#[account(mut,
    associated_token::mint = mint,
    associated_token::authority = treasury,
    associated_token::token_program = token_program)]
pub treasury_ata: InterfaceAccount<'info, TokenAccount>,   // always exists — created by `allow_mint`
```

- Transfer with `token_interface::transfer_checked` (supports Token and Token-2022).
- The Treasury ATA is created by platform-core when a mint is allowed, so consumers never need `init_if_needed` (the relayer forbids creating ATAs anyway). It is not closed when a mint is disallowed.
- **True 1/1 NFTs** (`decimals == 0 && supply == 1 && no mint authority`) get **no** Treasury ATA, because NFTs carry no fee. Never collect a fee for them.
- Token-2022 mints are filtered at `allow_mint` (error 6005): `PermanentDelegate`, `TransferFeeConfig`, `TransferHook`, `NonTransferable`, `DefaultAccountState` = frozen, and `MintCloseAuthority` with an authority set are rejected. A closable mint could be re-created later with new extensions, so it is refused outright.

**Collect fees once per asset, after the match settles** (anyone can trigger it), not on every claim and **never at boost time**: a cancelled match must refund boosts in full, and fees already in the Treasury can only leave through an Admin withdrawal.

## 3. Fee math (use the same formula everywhere)

```rust
let fee = (amount as u128)
    .checked_mul(fee_bps as u128).ok_or(MyError::MathOverflow)?
    / 10_000u128;                              // rounds down — the remainder stays with the recipient
let fee = u64::try_from(fee).map_err(|_| MyError::MathOverflow)?;
let net = amount - fee;                        // fee ≤ amount because fee_bps ≤ 2_000
```

`fee_bps` is your **snapshot**, not the current config. Example: a 1 SOL ad at 100 bps → 0.01 SOL to the Treasury, 0.99 SOL to the game owner. No fee on NFTs.

## 5. The relayer and platform-core

- **platform-core is never sponsored by the relayer.** All its instructions are signed by operators or game owners with their own SOL: `register_game` and `transfer_game_owner` need three signers (the relayer accepts two), and `GameEntry` / `DefaultAd` are never closed, so relayer-paid rent could never return.
- **Your** program, when sponsored, only *reads* platform-core accounts (and writes lamports into the Treasury), so the relayer never needs to trust platform-core.
- Fees must come from your program's escrow, never from the relayer's fee payer.
- Your game's `game_authority` PDA signs inside the program (`invoke_signed`), so it does **not** count toward the relayer's two transaction signers (fee payer + user).
- The relayer registers programs **statically** (program ID + instruction discriminators + pinned deploy slot); it does not read `GameEntry`. Suspending a game therefore means `set_game_status(Suspended)` **and** removing the game program from the relayer policy (see the hub [`SKILL.md`](../../SKILL.md) §3 rule 3). Re-activating is also two steps: `set_game_status(Active)` and adding the program back to the policy (reviewed again if its deploy slot changed).

## 6. Frontends and indexers (TypeScript)

`@anchor-lang/core` 1.2.1 + `@solana/web3.js` 1.x:

```ts
import { PublicKey } from "@solana/web3.js";
export const PLATFORM_CORE_ID = new PublicKey("AJnPSYsn7J2muHfKztRtpZz5kBP94dWkNZLr9aMhu18G");
const pda = (...seeds: (Buffer | Uint8Array)[]) => PublicKey.findProgramAddressSync(seeds, PLATFORM_CORE_ID)[0];
const u16le = (n: number) => { const b = Buffer.alloc(2); b.writeUInt16LE(n); return b; };

export const configPda    = () => pda(Buffer.from("config"));
export const treasuryPda  = () => pda(Buffer.from("treasury"));
export const gameEntryPda = (gameProgram: PublicKey) => pda(Buffer.from("game"), gameProgram.toBuffer());
export const rolePda      = (role: number, member: PublicKey) => pda(Buffer.from("role"), Uint8Array.of(role), member.toBuffer());
export const allowedMintPda = (mint: PublicKey) => pda(Buffer.from("boost_mint"), mint.toBuffer());
export const defaultAdPda = (w: number, h: number) => pda(Buffer.from("default_ad"), u16le(w), u16le(h));
export const gameAuthorityOf = (gameProgram: PublicKey) =>
  PublicKey.findProgramAddressSync([Buffer.from("game_authority")], gameProgram)[0];   // under the GAME program
```

**List Active games** (no Anchor needed; offsets are part of the frozen layout):

```ts
import bs58 from "bs58";
const disc = idl.accounts.find(a => a.name === "GameEntry")!.discriminator;   // 8 bytes from the IDL
const accounts = await connection.getProgramAccounts(PLATFORM_CORE_ID, {
  filters: [
    { dataSize: 220 },
    { memcmp: { offset: 0,  bytes: bs58.encode(Uint8Array.from(disc)) } },
    { memcmp: { offset: 10, bytes: bs58.encode(Uint8Array.from([0])) } },      // status = Active
  ],
  dataSlice: { offset: 11, length: 32 },                                       // game_program only
});
const activeGames = accounts.map(a => new PublicKey(a.account.data));
```

**Show a default ad** when a slot has nothing approved:

```ts
const ad = await program.account.defaultAd.fetch(defaultAdPda(w, h)).catch(() => null);
// Show nothing if: no account · owner is not platform-core · cannot decode · enabled === false.
// (Anyone can send lamports to an empty PDA, so "an account exists" does not mean "an ad exists".)
// Check sha256(image bytes) === creative.image_sha256 before showing the image.
// If the image fails to load, show creative.text instead.
```

Default ads go through the same moderation pipeline as paid ads (AI moderation of image and text, `click_url` checks).

⚠️ Render `creative.text` as **plain text** (never HTML), and check the origin of `click_url` / `image_url` against an allowlist before showing them. On-chain, the program only checks that `click_url` starts with `https://`, and the `Moderator` role is held by the moderator Worker's online key: if that key leaked, it could set any `https://` link hub-wide.

## 7. Operating the hub (Admin and role holders)

Every instruction below is signed from a wallet with SOL (e.g. Phantom or CLI), never through the relayer. "X | Admin" means a holder of role X **or** an Admin may sign; the `auth_role_kind` argument says which of the two `RoleMember` accounts you attach.

| Instruction | Signed by | Effect | Event |
|---|---|---|---|
| `initialize(boost_fee_bps, ad_fee_bps, first_admin)` | the program's **upgrade authority** (front-run safe) | creates Config, Treasury, the first Admin | `Initialized` |
| `grant_role(role, member)` | Admin | creates `RoleMember` | `RoleGranted` |
| `revoke_role(role, member)` · `renounce_role(role)` | Admin · the member | closes `RoleMember`; the **last Admin can never be removed** (6002) | `RoleRevoked` |
| `set_fee(auth_role_kind, kind, fee_bps)` | FeeManager \| Admin | sets the boost or ad fee; > 2000 bps fails (6001) | `FeeChanged` |
| `register_game(auth_role_kind)` | GameRegistrar \| Admin **+ the game owner co-signs** | creates `GameEntry` (Active) | `GameRegistered` |
| `set_game_status(auth_role_kind, status)` | GameRegistrar \| Admin | Active ⇄ Suspended | `GameStatusChanged` |
| `transfer_game_owner()` | current owner **+ new owner co-signs** | changes `owner` | `GameOwnerChanged` |
| `force_set_game_owner(new_owner)` | Admin only (owner lost their key) | changes `owner` (use a system-owned wallet) | `GameOwnerChanged` |
| `allow_mint(auth_role_kind)` · `disallow_mint(auth_role_kind)` | AllowlistManager \| Admin | creates / closes `AllowedMint` (allow also creates the Treasury ATA) | `MintAllowed` · `MintDisallowed` |
| `withdraw_sol(amount)` · `withdraw_token(amount)` | Admin | Treasury → `to` (`withdraw_sol` never leaves it below rent-exempt, 6004) | `TreasuryWithdrawn` |
| `create_default_ad` · `update_default_ad` · `set_default_ad_enabled` | Moderator \| Admin | default ads (in practice created by ad-pool's moderator Worker on an Admin's signed request) | `DefaultAdSet` |

**Getting a game registered.** `register_game` requires the game program to be executable and owned by the **upgradeable** loader, and refuses platform-core itself and the core programs that are also upgradeable-owned (Token, Token-2022, ATA, Stake, Address Lookup Table, Config). It is created once per program and **never deleted**; a game can only be suspended. Send the hub Admin: your program ID, the owner wallet (system-owned, with SOL, ready to co-sign) and the cluster.

Nothing can be deleted by design: there is no `close_config`, `unregister_game` or `close_treasury`.

## 8. Errors

| Code | Name | Typical cause |
|---|---|---|
| 6000 | `Unauthorized` | signer lacks the role, or the attached `RoleMember` is not theirs |
| 6001 | `FeeTooHigh` | `fee_bps` > 2000 |
| 6002 | `LastAdmin` | removing the only Admin |
| 6003 | `GameProgramNotExecutable` | registering a non-program account |
| 6004 | `InsufficientTreasury` | withdrawal would leave the Treasury below rent-exempt |
| 6005 | `UnsupportedMintExtension` | mint has a forbidden Token-2022 extension or a close authority |
| 6006 | `InvalidAdSize` | width or height is 0 |
| 6007 | `CreativeFieldTooLong` | `image_url` > 200 · `text` > 120 · `click_url` > 200 bytes |
| 6008 | `InvalidClickUrl` | `click_url` does not start with `https://` |
| 6009 | `InvalidImageHash` | `image_sha256` is all zeros |
| 6010 | `MathOverflow` | — |
| 6011 | `InvalidMember` | the all-zero pubkey as a role member, first Admin or new game owner |
| 6012 | `InvalidGameProgram` | not upgradeable-loader owned, or a denied core program |

Errors **your** program raises while checking platform-core accounts are Anchor's: 3012 `AccountNotInitialized` (e.g. revoked role, unregistered game, mint not allowed), 2006 `ConstraintSeeds` (wrong game / role / mint), 3007 `AccountOwnedByWrongProgram` (fake account), 3001 / 3002 discriminator errors (wrong account type).

## 9. Layout and versioning

- Every account starts with the 8-byte discriminator, then `version: u8` (= 1) and `bump: u8`, and ends with reserved bytes. Fields are never reordered and seeds never change; new fields consume reserved bytes.
- `GameEntry` byte offsets (stable): `status` 10 · `game_program` 11 · `owner` 43 · `game_authority` 75 · `game_authority_bump` 107 · `registered_by` 108 · `registered_at` 140 · `updated_at` 148 · reserved 156–219.
- `PlatformConfig` offsets: `boost_fee_bps` 10 · `ad_fee_bps` 12 · `admin_count` 14 · `treasury_bump` 16.
- Full layout of every account: [`specs/designs/01-account-layout-v1.md`](../../specs/designs/01-account-layout-v1.md). Interface changes ship as a new IDL version and are announced before deploy.
